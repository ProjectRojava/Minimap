# ADR-0014: Ongoing objectives

- **Context**: an objective such as "keep internal systems healthy" never ends. Leaving its target date empty already worked, but nothing said *why* it was empty (perpetual or forgotten), a "done" status made no sense for it, it had no way to be noticed when it drifted, and it was listed with the undated goals.
- **Decision**: an objective is either a **goal** (has an end) or **ongoing**. `objectives.ongoing` (0/1, default 0) plus `review_every_days` and `last_reviewed_on` (migration 0011). An ongoing objective has **no target date and is never done** (both enforced in `store::objectives`; switching a goal to ongoing clears the date and turns "done" into "on track"; to end one, archive it). Its review is due `review_every_days` after `last_reviewed_on` (or after creation), `Objective::review_due()` / `review_overdue_days(today)`.
- **Health**: no lateness for an ongoing objective. A review that is overdue holds the objective at **amber** with the reason *review overdue by N days (due D, every M days)* (`health::objective_health` takes `Option<&ReviewFacts>`); the roll-up of contributors is unchanged. With nothing contributing it is idle, as before (the row still carries the review fields). A "nothing finished in N days" signal was left out: for watching-type objectives it is mostly noise, and the review already asks "is this still fine?".
- **Where it shows**: the Objectives list puts ongoing ones in their own last group (`core::objectives::arrange`); the objective pane has a Kind switch, a review rhythm, *Last reviewed* and *Mark reviewed* (an ordinary update, so undo and the activity log cover it); *This week* and the Weekly review (new step 7, "Ongoing") list reviews overdue or due by Sunday (`core::objectives::reviews_due`); the Overview and the status report say "ongoing" and flag a late review.
- **Why fields, not a node type or a recurring task**: it is the same object (it has projects, tasks, health, colour, notes); only its end is different. A recurring "review X" task would work but cannot turn the objective itself amber, and would be one more thing to create per objective.
- **Deviation**: `CLAUDE.md` §4's Objective gains `ongoing`, `review_every_days`, `last_reviewed_on` and the rule that an ongoing objective has no target date and is never done.
