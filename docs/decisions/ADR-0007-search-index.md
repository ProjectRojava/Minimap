# ADR-0007: Search index maintained by triggers, typo tolerance from the term list

- **Context**: spec 11 wants sub-100 ms search over titles, descriptions, names and note bodies, kept in sync "via triggers or repository writes", and (answered) typo-tolerant matching. FTS5 itself is prefix-only.
- **Index**: migration 0007 adds `search_docs` (node type, id, archived flag, integer rowid) and an FTS5 table `search_index(title, body)` (`unicode61`, accents folded). **Triggers** on all eight node tables keep them current, so every write path (repos, archive/unarchive, hard delete, checklist conversion, future importers) is covered without each repo remembering. Updates only fire when an indexed column or `archived_at` changes.
- **Typo tolerance**: FTS5 has no fuzzy mode, so `fts5vocab` exposes the indexed terms and `minimap-core::search` finds terms within an edit distance (none for words under 4 letters, one for 4-7, two for 8+; swaps count once; a word may also be a typo'd start of a longer word). Alternatives are OR-ed into the FTS expression, so ranking and speed stay FTS5's. This runs **only when the as-typed (prefix) query finds nothing**, and only for words that match no indexed term, which keeps the common case to one fast query and avoids "corrections" of words that were right.
- **Note bodies**: mentions are stored as `@[Name](node:<uuid>)`; indexing them raw would make ids and the word "node" searchable. The note trigger calls a SQL function `mention_text(body)` (core `notes::mentions_as_names`) that the store registers on every connection in `init` before migrating. **Consequence**: any connection that writes notes must register it; one that doesn't (a bare `sqlite3` shell, a future tool) can read the database but its note writes fail. Backup/rekey copy pages and are unaffected.
- **Alternatives rejected**: scanning all text in Rust (no FTS5, slower as notes grow, no ranking); repository-side index writes (many write paths to miss); storing note bodies pre-stripped in a second column (duplicates data).
- **Cost**: the index duplicates the searchable text inside the database file. Measured on 2.9k nodes, 400 notes of 400 words and 20k terms: prefix search ~0.5 ms, typo retry ~20 ms (release; ~75 ms unoptimised debug build).
