# ADR-0009: Report export through a save-only dialog, with a checked path

- **Context**: spec 19 ends the weekly review with "Export as Markdown status report" to a file the user picks. CLAUDE.md §6 anticipates "dialog/fs permissions export/backup need" but wants nothing broader than necessary for the webview, and §1 forbids anything leaving the device except to a destination the user chose.
- **Decision**:
  - Add `tauri-plugin-dialog` (2.8.x) and grant the main window **only `dialog:allow-save`**. No open/message dialogs and **no `fs:*` permissions**: the webview can ask the OS where to save, and nothing else.
  - The webview calls `window.__TAURI__.dialog.save` (global API, `withGlobalTauri`), then our own command `export_markdown(report_kind, params, path)`. The file is written by Rust with `std::fs::write`, not by a plugin.
  - Because the path string comes from the webview, `export_markdown` accepts only an **absolute path ending in `.md` or `.markdown`, in an existing folder, that is not itself a folder**, builds the whole report first, then writes that one file and nothing else (no temp or sibling files). Anything else is refused as `invalid` and writes nothing.
  - The report text comes from a template stored in `settings` (`report_template`, validated by core on save), so what is exported is always generated from Minimap's own data, never from webview-supplied content.
- **Consequences**: backup (spec 20) and full export (spec 26) will need to choose a folder or file the same way; they should reuse this pattern (save-only dialog, backend-side path checks) and add `dialog:allow-open` or a directory picker only if truly needed, with a new note here. The dialog plugin pulls in `tauri-plugin-fs` as a dependency for its scope handling; its commands are not exposed to the webview because no `fs:*` permission is granted.
- **Alternatives rejected**: the backend opening the dialog itself (a command that blocks on UI is awkward in the async command model and diverges from the spec's `export_markdown(…, path)` signature); granting `fs:allow-write-text-file` and writing from the webview (a far broader capability than one save); writing to a fixed folder without asking (the user must choose the destination).
