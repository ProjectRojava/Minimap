# Minimap knowledge graph

**Read this first, then open only the files it points to.** It is a map of the code: what exists, how it connects, where each rule is enforced and tested. It is not a spec (see `CLAUDE.md`, `docs/features/`) and not a tutorial.

- **Keep it current**: any change that adds, removes, renames or re-wires something listed here must update this file in the same change (checklist in §14). If something here disagrees with the code, the code wins; fix this file.
- **Format**: every thing has an id `kind:name` (`crate:`, `mod:`, `fn:`, `cmd:`, `table:`, `type:`, `ui:`, `spec:`, `rule:`). Edges are written `A -> B  (relation)`. Grep an id to find every line that mentions it, e.g. `grep -n "cmd:add_edge" docs/knowledge-graph.md`.
- **Last verified against code**: after the notes on This week (spec 36); before that the detail pane sections (spec 35); before that the Markdown box (spec 34); before that sub-tasks apart from blocking (spec 33, ADR-0017); before that task types (spec 32, ADR-0016); before that the card menu and linked tasks (spec 31) and the removal of subtasks (ADR-0015); before that ongoing objectives (spec 30, ADR-0014), subtasks (spec 29, ADR-0013, withdrawn), reference links (spec 28), before that the Projects list's narrow layout, objective colours (ADR-0012) and the Tasks board). All specs are implemented (29 withdrawn) (manual checks pending).

## 1. Orientation

Local-first desktop app (Tauri 2.12 shell, Leptos 0.8 CSR/WASM UI built by Trunk + Tailwind v4, SQLite via rusqlite/SQLCipher). Rust everywhere, no npm. Single user; people are records. Network allowed only for user-connected features (ADR-0011, superseding ADR-0002); no telemetry.

```
UI (wasm)  --invoke-->  Tauri commands  --rules-->  core (pure)
                              |                        
                              +--------------------->  store (SQLite + activity log)
all of them share DTOs from crate:minimap-types
```

Status: M0 done (progress.md M0 checkboxes are stale), M1 in progress: specs 01-02 done, 03-27 implemented (manual check pending).

Common columns: `id` (uuid v7 TEXT), `created_at`, `updated_at`, `archived_at` (soft delete). Dates `YYYY-MM-DD`; timestamps `YYYY-MM-DDTHH:MM:SS.mmmZ` UTC (`mod:timefmt`).

Defaults: priority 3, weekly capacity 40h, project `planned`, task `todo`, task type none (the list in Settings starts as `default_task_types()`: Design, Build, Decision, Review, Research, Bug, Admin), objective `on_track`, decision `proposed`, note kind `general`.

### 3.3 Activity log (`table:activity`)
Actions (`type:ActivityAction`): created, updated, archived, **unarchived**, **deleted**, edge_added, edge_removed (last-but-two are additions beyond CLAUDE.md, ADR-0003). `diff` = `{field: [old, new]}`; created = `[null, value]` for every non-meta field; archive = `{archived_at: [null, ts]}`; edge rows = `{edge: [null|desc, desc|null]}` and are attached to the edge's **from** node. History survives hard delete (no FK).

### 3.4 Sync and attachment tables (migration 0008, spec 22, ADR-0011)
- `table:edges.updated_at` and `table:settings.updated_at`: kept by **triggers** (`edges_stamp_insert/update`, `settings_stamp_insert/update`), so no write path can forget them; the triggers stand down while `app_meta.local.merging` exists (a merge is applying another device's rows). `settings` deletes leave a tombstone (`settings_tombstone`).
- `table:tombstones(kind, id, deleted_at, lifted_at)`: written by every hard delete (`nodes::delete`, attachment rows of a deleted node). Active while `lifted_at IS NULL OR deleted_at > lifted_at`; a recovery sets `lifted_at`; both columns merge by taking the later value.
- `table:attachments(id, node_type, node_id, sha256, file_name, mime_type, size_bytes, created_at, updated_at, archived_at)`: no FKs (polymorphic like edges); the bytes live in the media cache and on Drive under `sha256`.
- `table:app_meta` rows with the `local.` prefix are **device-local** (`local.device_id`, `.device_name`, `.vault_key`, `.drive_refresh_token` (only without a keychain), `.drive_client`, `.sync_state`, `.sync_dirty`, `.banner_until`, `.merging`): never merged, never in a snapshot, kept across a restore (`store::meta`). Per-device settings (`theme`, `backup_folder`, `auto_backup`; `settings::LOCAL_ONLY`) are not synced either.

## 5. Core crate (`crate:minimap-core`, pure)
- `mod:edge_rules`: `is_allowed`, `validate_types`, `validate_attrs`, `validate(edge_type, from:NodeRef, to:NodeRef, attrs)` (self-edge first), `must_be_acyclic` (blocks, depends_on, reports_to, supersedes), `EdgeRuleError{NotAllowed,SelfEdge,BadAttr}`. Attribute rules are schema-driven: `attr_schema(edge_type) -> Vec<AttrSpec>` is the single definition used by `validate_attrs` and by editors; `link_options(node_type) -> Vec<LinkOption>` lists every relation addable from a node type in both directions (exactly what the matrix allows; `relates_to` symmetric so offered once, outgoing).
- `mod:cycles`: `find_cycle(existing:&[(from,to)], from, to) -> Option<Vec<Uuid>>` returns `[from,to,...,from]` (BFS over petgraph `DiGraphMap`).
- `mod:layout` (spec 18, generic Sugiyama-style): `layout(sizes, edges, Params) -> Layout{nodes: Placed{x,y,w,h,layer}, routes, width, height}` (Kahn layers + sources pulled right, virtual lanes for long edges, barycentre sweeps keeping the fewest crossings, pool-adjacent-violators vertical placement), `crossings_of`, `LayoutError::Cycle`. `mod:dependency_graph`: `build(GraphInput{tasks,edges,projects,teams,today}, &GraphFilter) -> Result<DependencyGraph, GraphError{Cycle,TooLarge}>`: tasks via `blocks` or projects via `depends_on` (drawn needed -> dependent), project/team (incl. sub-teams)/objective filters AND-ed, one-hop dimmed context, unlinked and finished hidden by default, max 400 nodes, critical/late flags and critical links from the schedule.
- `mod:attachments` (spec 22, pure): `classify(file_name) -> (AttachmentKind, mime)` over an allow-list (images incl. SVG, md/txt/csv/tsv/json, PDF, Word, Excel, PowerPoint; **no executables or scripts**; refusal text lists what is allowed), `check_size` (1 byte .. 250 MB), `clean_name` (no folders/control characters, <= 200 chars keeping the extension), `markdown(id, name, kind)` (`![name](attachment:<id>)` for pictures, `[name](attachment:<id>)` otherwise), `is_sha256`; a test keeps `types::ATTACHMENT_EXTENSIONS` equal to the kind table.
- `mod:sync` (spec 22, pure): `remote_wins(local_updated, local_hash, remote_updated, remote_hash)` (later write wins; equal timestamps go to the larger `fnv1a` content hash so both devices choose the same row; identical = no change), `fnv1a`, `links_to_drop(&[LoopLink]) -> Vec<usize>` (oldest links kept; one that would close a loop with the kept ones is dropped; order-independent, proptest), `save_wait_ms(first_unsaved, last_change, now)` (idle 5 s, never later than 30 s after the first change), `backoff_secs` (5/30/120/600), `POLL_SECS` = 15, device/checkpoint file names (`device_file_name`, `parse_device_file_name`, `checkpoint_name`, `parse_checkpoint_name`, `is_valid_device_id`), `checkpoint_due` (first save of each UTC hour), `checkpoint_prune_plan(files, hourly, daily)` / `default_checkpoint_prune_plan` (newest 24 stay, then the newest of each of 30 more days), `OFFLINE_WARNING_DAYS` = 3, `ORPHAN_MEDIA_GRACE` = 7 days.

## 9. Key flows
- **First run**: UI `FirstRun` -> `get_self_person` None -> prompt -> `create_self_person` -> `DataVersion` bump.
- **Group objectives**: UI toggle -> `list_objectives(grouping)` -> store rows -> `core::objectives::arrange` -> groups labelled "Q1 2027" ... "No date".
- **Move task on the board**: card `dragstart` -> column `drop` -> `pending[id] = status` (card jumps at once) -> `update_task{status}` (store sets/clears `completed_at`, a repeating task made `done` makes its next one in the same tx) -> `finish` bumps `DataVersion` -> `list_tasks` reloads -> `pending` cleared. Failure: toast + the reload puts the card back.
- **Move project on the board**: card `dragstart` (sets `dataTransfer`, WebKit needs it) -> column `drop` -> `update_project{status}` -> activity `updated` row -> `DataVersion` bump.
- **Archive project**: `preview_archive_project` (active tasks) -> choose "archive tasks too" or "move to inbox" -> `archive_project` (single tx).
- **Paste a task list**: textarea with newlines -> `parse_task_lines` -> preview (needs > 1 line) -> `create_tasks_bulk` (one tx, default assignee Me, project = the project filter unless in the inbox).
- **Waiting-on state**: age/stale/snoozed/overdue are computed in core against `store::today()` (UTC date) every time the list is read; snoozing sets `follow_up_on`, which hides the item until that date. Overview (15) and This week (16) will read `get_waiting_on` and its `stale` flag.
- **Write a note**: typing -> debounce -> `update_note(body)` -> store updates the row, folds the activity entry, syncs `mentions` edges -> `DataVersion` bump (detail/checklist/lists refresh; the textarea is not re-rendered). `@` -> picker -> token inserted at the caret (UTF-16 <-> byte conversion in `mentions.rs`).
- **Convert a `[ ]` line**: unsaved text flushed -> `convert_checklist_item(note, line, text)` -> task created + line becomes `- [x] @[title](node:task)` -> UI reloads the note body into the editor.
- **Overview**: `/` -> `get_portfolio_overview` (version-keyed) -> core `overview::build` + stale waiting-ons; project and objective panels read their own Health from the same command. Thresholds: Settings -> Project health -> `update_settings{health}` (validated) -> every verdict follows.
- **What if**: "What if this slips?" button (or the palette / sidebar) -> `Scenario` -> `run_impact_analysis(slips)` (version-keyed, so it refreshes after edits) -> core `analyze` -> report. "Apply to plan..." -> `preview_apply_slips` -> confirm -> `apply_slips` (re-derives, one transaction) -> scenario cleared, `DataVersion` bump.
- **Schedule**: project panel -> `get_schedule(Project(id))` (version-keyed, so edits to tasks, estimates, dates and blocks links redraw it) -> core `compute` over all open tasks -> forecast line + critical list + `timeline::layout` -> SVG.
- **Quick-add**: palette text with a keyword -> `parse_quick_add(text, choices)` -> core `plan` (names matched against `store::quick_add::directory`) -> preview; unclear names are answered into `choices` (re-parse each time); Enter when `ready` -> `commit_quick_add` re-parses (never trusts the UI) -> one transaction -> toast + node opens in the pane.
- **Search**: keystroke -> `search(query)` -> core words -> FTS5 prefix query -> hits; no hits -> vocabulary + typo alternatives -> second query. The index is kept by triggers on every node table, so no repo writes to it.
- **Autosave and sync (spec 22)**: any command that writes -> `run_vault` sees `total_changes` move -> `Engine::note_change` (unsaved, remembered across a restart) -> the `drive-sync` thread's `tick`: 5 s after the last change (30 s cap) `push` = snapshot (export keyed with the vault key, device-local rows scrubbed) -> upload over this device's own file (old file stays until complete) -> hourly checkpoint -> attachment blobs uploaded. Every 15 s `pull`: list `devices/`; a device whose stamp changed is downloaded (no DB lock), `merge` Preview then Apply (one transaction, repairs reported); a merge that changed anything bumps `data_revision` (UI reloads) and marks this device unsaved so the others get the combined result; once nothing differs nothing more is uploaded. Failures keep the old snapshot and back off; auth/key problems wait for the user.
- **Connect Google Drive**: Settings -> `connect_drive` -> browser sign-in -> Drive empty: new vault key, recovery key shown once, everything uploaded; Drive has data and this device has the matching key: join; otherwise recovery key typed -> `finish_drive_connect` -> a device with no data of its own adopts the newest snapshot (page reloads), one with data merges (a `pre-sync` backup first).
- **Attach a file**: picker path / pasted or dropped bytes -> checks -> encrypted into `<data>/media/<sha256>.bin` -> row + activity -> (when connected) the next save uploads the blob; other devices get the row by merge and fetch the bytes when first opened.
- **Recover from a checkpoint**: Settings -> `recover_checkpoint(name)` -> download -> `pre-recover` backup -> `MergeMode::Recover`: whatever differs from that copy comes back as new edits (tombstones lifted) and reaches the other devices; newer items stay.
- **Recurring (spec 27)**: a task is set to done (any screen -> `update_task` -> `tasks::update_in_tx`) -> its rule is handed to a new task due on `next_for_task` (one transaction, one undo step) -> lists reload. A repeating note: the `recurring-notes` thread (start, then every 10 minutes) -> `notes::generate_due(today)` -> a new note for the latest due date from the template and open items, the rule moves on.
- **Export everything (spec 26)**: Settings -> Export… -> folder picker -> `export_all(path, format)` -> `collect` (all rows incl. archived) -> new `minimap-export-<time>.part` folder: JSON files, attached files from the local cache, optional Markdown, README, manifest -> renamed into place. The files read back into the same structs.
- **Undo (spec 25)**: a command via `AppState::run` writes activity -> `record_since` (rows after the marker -> `core::undo::plan` -> a `Step` with its label from `headline_text`) -> Ctrl/Cmd+Z -> `undo_last` -> `store::undo::apply` (checks, then the inverse through the repos, one transaction) -> the rows it wrote become the redo step -> toast + reload. Session only; cleared by restore/recover/Drive join/demo seed.
- **Estimate**: text field -> `set_task_estimate` -> core `parse_estimate` with the stored hours-per-day -> `estimate_days` (existing estimates never rewritten when the setting changes).
- **Contribution weight**: UI input -> `update_edge_attrs` -> core `validate_attrs` (0-1) -> `edges::update_attrs` (+activity).
- **Add link**: UI -> `cmd:add_edge` -> `check_new_edge` (matrix, attrs, self-edge, one parent / one level for `subtask_of`, cycle for blocks/depends_on/reports_to, error text lists node names: "Can't add this link: this would create a loop — A → B → A") -> `edges::add` (tx + activity).
- **Generic link**: pane Links -> `list_link_options(node_type)` -> choose relation -> search candidates (`list_node_summaries` per allowed type, minus self and already-linked) -> `add_edge` (rules + cycle check run in the command; a loop toast names the path) -> `DataVersion` bump. Attribute inputs -> `update_edge_attrs`.
- **Archive person**: `preview_archive_person` (active assigned tasks) -> confirm -> `nodes::archive` (person + edges in one tx; self refused).
- **Nest team**: `update_team` with `Patch::Set(parent)` -> `check_new_parent` (parent active, no loop incl. archived teams) -> `teams::update`.

## 13. Conventions and gotchas
- No `unwrap/expect` outside tests/main setup (exceptions: `build.rs`). Domain rules in core; commands thin; UI has no business rules; all SQL in store, parameterized (table/column names are compile-time constants only).
- Every write is a transaction that also writes `activity`.
- Specs: implement only `Status: Ready` (user may override by asking); record answers to open questions + deviations in the spec/an ADR.
- Commits: user commits; end messages with the attribution line from the session system reminder.
- Full-height overlays (detail pane scrim) start at `top-8`, below the title bar.
- `ui/dist/` and `src-tauri/gen/` are build output (in `.gitignore`; `gen/` was committed earlier and may still be tracked).
- WSL: `libEGL`/`MESA` warnings from WebKitGTK are harmless.
- Edge attribute changes (team role, contribution weight) go through `update_edge_attrs`, one `updated` row on the from node. The editor's attribute controls come from `edge_rules::attr_schema`, so a new attribute is one schema entry.
- Priority: 1 = highest everywhere.
- Anything the UI needs that is a business rule (sorting, grouping) is computed in core and returned by a command; the UI crate can't depend on core.
- Migrations that need data fixes use `M::up_with_hook` (runs after the SQL, same tx); the app DB is migrated on launch (there is no pre-migration backup yet, spec 20).
- HTML5 drag-and-drop in the webview needs `dragDropEnabled: false` and `dataTransfer.setData` on dragstart.
- Sub-tasks (spec 33, ADR-0017) are organisation only: never read `subtask_of` in the schedule, graph, impact, capacity or health (spec 29's version did, ADR-0015 removed it). Sequence with `blocks`; "parent" and "child" mean part-of, never blocking.
- Row shortcuts (`x s d a 1-5`) and `n` are global keys that screens opt into via `ListNav::on_row_key` / `on_new`; screens that don't register ignore them. Row key `a` focuses the assignee dropdown's button and `d` the due date's text box; Enter/Space/arrows then open them.
- Note bodies are private: tracing never logs them and activity stores only sizes. The rendered Markdown has no hrefs and no images: external links show their URL in a tooltip and, when clicked, open through `open_link` (http/https/mailto only); a single newline is a line break (`render` turns soft breaks into hard ones).
- Tailwind classes live in Rust source; Trunk's Tailwind scans `.rs` files.
- **Connections that write must register `mention_text`** (`register_functions` in store `lib.rs`, called by `init`): the notes search trigger calls it. Tests that build a raw `Connection` and migrate it call `register_functions` first.
- **Sync gotchas (spec 22)**: the SQLCipher backup API can't copy plain -> encrypted, so snapshots use `sqlcipher_export` (`snapshot::create`); `security::replace_live` refuses an in-memory database, so engine/restore tests use file databases; `reqwest` 0.13 needs the `query` and `form` features; Drive's resumable protocol answers `308` for "keep going", so chunk PUTs are sent once and a lost answer is resolved by asking the server where it got to; `pkill -f` patterns can match the shell running them; a command that writes through `AppState::run` marks changes to save automatically, but the engine's own bookkeeping writes go through `Host::with_db` (no marking); device-local state must use `local.*` meta keys or `settings::LOCAL_ONLY`; every hard delete must go through `nodes::delete` (tombstones); an edge or setting write needs nothing extra (triggers stamp `updated_at`). `src-tauri/build.rs` re-runs when `.env` or the two Google variables change (rebuild to pick up new credentials). Without Google credentials only the mock/folder paths are tested: connect, upload and download against real Drive need a manual check.
- **Fixed "today" in command tests**: `schedule_at`, `with_world_at`, `overview_at`, `review_at`, `report_at` take today as a parameter (the `*_impl` / command versions pass `store::today()`); the demo-data snapshot tests use Wednesday 2027-03-03. After changing the seed or any rule it exercises, review with `INSTA_UPDATE=always cargo test -p minimap demo` and read the `.snap` diff. A table that must stay one row per line (`task_table`, `BLOCKS` in `demo.rs`) carries `#[rustfmt::skip]`.
- **Tests and a local `.env`**: with Google credentials in `.env` the build bakes the OAuth client in, and two `commands::sync` tests (`a_new_install_is_local_only_*`, `settings_keep_the_client_*`) assume there is none. Run `MINIMAP_GOOGLE_CLIENT_ID= MINIMAP_GOOGLE_CLIENT_SECRET= cargo test --workspace` (the environment wins over `.env`).
- Themes: dark is the default (input.css + window `backgroundColor` + `settings.theme`); no theme JS (CSP), so a non-default theme can flash dark for a moment at launch (cache narrows it). Palettes are adapted; `fg`/`muted`/`danger` of several are nudged to pass the contrast tests.
