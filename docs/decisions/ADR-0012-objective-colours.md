# ADR-0012: Every objective has a colour that its projects and tasks wear

- **Context**: objectives, projects and tasks are one chain (task → project → objective) but the screens looked alike, so you could not see at a glance which objective a project or a task serves. The user asked for an eye-catching colour per objective, handed down to projects and tasks, with no two objectives alike. This widens the colour rule of ADR-0008 ("colour has four jobs and no others").
- **Decision**: a fifth job for colour, **identity of an objective**.
  - **Derived, not stored.** The active objectives are ranked by id (UUID v7 ids sort by creation time) and rank `n` takes hue `n` of a hand-picked palette (`PALETTE` in `ui/src/components/objective_colour.rs`): blue, orange, green, violet, pink, olive, teal, indigo. The first eight are at least 35° apart and avoid red and amber, which already mean overdue and needs-attention. The second objective is always far from the first (170°). Past eight the hues keep spreading by the golden angle (best effort: with that many objectives some will be alike). No schema change, no migration, nothing to sync: the same data gives the same colours on every device.
  - **Readable on every theme.** Only the hue is per objective; saturation and lightness come from the theme's kind (`:root` / `:root[data-kind="light"]` in `input.css`, `data-kind` set by `theme.rs`). A test checks every hue at those values against canvas and panel of all 17 themes (3:1, the bar for non-text marks).
  - **Where it shows.** A dot, tinted chip (hue + the objective's name) or 3px edge: Objectives rows, Projects (list group headings, rows with an Objective column, board cards), Tasks (board cards with chips and an edge, list rows with an edge and a dot). A project's colour on a row is its first objective (under an objective's heading in the list: that objective); a task wears its project's. A task linked straight to an objective but in no project is not coloured (rare).
  - **Never the only signal.** Chips carry the objective's name; dots and edges have it as a tooltip; the chip text is the normal text colour (the hue is the border, tint and dot), so no contrast rule applies to the words.
- **Consequences**: archiving an objective moves the later ones up a colour (the ranking is over active objectives, which is what the list gives the UI). If colours must stay fixed or be chosen by hand, store a colour slot on the objective instead (a migration, `Objective` field, demo data, export, undo and a sync rule for two devices picking the same slot). Projects and tasks cost one extra `list_projects` call per data change (cached in the shell's `ObjectiveColours` context).
